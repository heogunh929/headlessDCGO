## 1. 개요 / 목적
헤드리스 C# 엔진 위에서 AI 정책을 학습시키는 내부 환경. 단순 "봇 만들기"가 아니라 최종적으로
**메타 진화 시뮬레이터 + 밸런스 분석 엔진**을 지향한다:
- 발매 순서대로 카드풀을 열었을 때 **실제 역사의 메타가 재현되는가, 혹은 인간이 못 찾은 최적해가 나오는가**를 관찰.
- 대전 로그로 **카드/덱 기여도·밸런스**를 진단.
- 여기서 학습된 정책 스냅샷은 곧 **아레나 봇**이 된다(같은 seat 프로토콜·관측 스키마 공유).

## 2. 범위
### 2.1 범위 내
- 덱-조건부 플레이 정책 학습(SB3/MaskablePPO), 스냅샷 리그(과거 자신과 대전), 덱 레시피 로더(정규화),
  덱 진화(GA, 후속), 대량 병렬 대전, 로그 레벨 인프라, 신규 덱 편입(파인튜닝), 밸런스 분석(후속).
### 2.2 범위 외 (초기)
- semantic 효과 태깅(정교 밸런스 분석용 — 실제 분석 니즈 + 세트 포팅 후), 제로샷 일반화 최적화(포기),
  덱 성향 보상(불채택), 상용 규모 분산 학습.

## 3. 핵심 개념 / 구조
- **이중 루프**: 바깥=**덱 공급원**(GA 진화 / 손으로 고정 / 랜덤 배급), 안쪽=**플레이 정책**(SB3 학습 / 고정 스냅샷).
  두 축은 **독립 토글**(GA on·off × SB3 on·off)로, 조합해 여러 실험 모드를 구성한다.
- **덱-조건부 단일 정책**: 덱을 관측(카드-ID 임베딩)에 넣어, **한 정책이 임의 덱을 플레이**한다.
  이것이 덱 진화(바깥 루프)가 덱을 바꿔도 안쪽으로 평가 가능하게 하는 전제.
- **스냅샷 = 공통 화폐**: 학습 중 얼린 정책 스냅샷이 (a)리그의 과거 상대(화석) (b)아레나 봇 으로 재사용.
- **한 대전 로그, 세 소비자**: RL(정책)·GA(덱)·분석(밸런스)이 같은 로그를 각도만 달리해 소비.

## 4. 확정 제약 / 결정 사항
- **C-1** 안쪽 루프 트레이너 = Python + sb3-contrib MaskablePPO(엔진 인터페이스 준비됨).
- **C-2** 정책은 **덱-조건부**(카드-ID 임베딩). 임의 덱 대응이 목적.
- **C-3** 상대 = **스냅샷 리그**(순수 셀프플레이 아님) — 비정상성 완화, 다양성 보존.
- **C-4** 보상 = **순수 승패(terminal ±1)로 시작.** 셰이핑·덱 성향 보상은 기본 미채택(필요 시 최소·감쇠).
- **C-5** 덱 공급원과 플레이 정책은 **독립 토글**(모드 조합 가능).
- **C-6** 시작 순서 = **과거 덱 레시피 고정 + SB3 학습(GA off)** → 리그 안정화 → **그 다음 GA**.
- **C-7** 아레나와 **엔진·seat 프로토콜·관측 스키마·로그·스냅샷을 공유**한다(별개 시스템 아님).

## 5. 기능 요구사항 (FR)

### 5.1 플레이 정책 학습
- **FR-1.1** 시스템은 덱-조건부 정책을 self-play/리그로 학습할 수 있어야 한다(관측에 덱 정체=카드-ID 반영).
- **FR-1.2** 정책 형태는 feed-forward(Mlp)↔RecurrentPPO 교체 가능해야 한다(순차계약 유지).
- **FR-1.3** 보상은 기본 순수 승패(±1). 보상 계산기는 교체 가능해야 한다(최소 셰이핑 실험 여지).

### 5.2 리그 / 스냅샷
- **FR-2.1** 학습 중 정책을 **스냅샷으로 얼려** 상대 풀에 추가할 수 있어야 한다.
- **FR-2.2** 스냅샷 얼리는 기준은 **시간/스텝 기본 + 실력 게이트 옵션**을 지원한다.
- **FR-2.3** 상대 샘플링은 **최근 위주 + 가끔 과거 랜덤**(과적합/순환 방지)을 지원한다.
- **FR-2.4** 스냅샷에는 **덱·시점 메타**를 태깅해, 과거 메타 화석 대전이 가능해야 한다.
- **FR-2.5** 스냅샷은 아레나 봇으로 그대로 배포 가능해야 한다(관측 스키마 버전 일치).

### 5.3 덱 공급 / 레시피 로더
- **FR-3.1** 덱 레시피를 **JSON/파일로 던져** 코드 수정 없이 실험할 수 있어야 한다.
- **FR-3.2** 로더는 외부 시스템 레시피 포맷을 **정규화**한다: 헤더 제거, 구분자 정규화(하이픈→언더스코어),
  일러 변형(`_P1` 등) collapse, **중복=매수 집계**, 타입 기반 **메인/디지타마 분리**, 미지원 카드 명시 실패.
  (P·LM 등 자체 효과 카드는 특별 취급 없이 일반 조회.)
- **FR-3.3** 정규화기는 **카드-ID 임베딩 vocab과 공유**한다(같은 카드는 같은 정체로 일관).
- **FR-3.4** GA가 생성하는 덱도 **같은 레시피 포맷**으로 표현되어, 손 던진 덱과 동일 통로를 쓴다.

### 5.4 덱 진화 (GA, 후속)
- **FR-4.1** 덱 모집단을 승률 적합도로 진화(교배·변이·도태)할 수 있어야 한다(안쪽 정책이 안정된 뒤 활성).
- **FR-4.2** 변이는 **로그 기반 카드별 기여도**로 유도할 수 있어야 한다(눈먼 선택압 완화).
- **FR-4.3** 기여도의 상관/인과 착시는 **반사실(카드 제외 변종 대전)**로 검증한다.
- **FR-4.4** 진화하는 덱 모집단 자체가 **관찰 대상(창발 메타)** 으로 조회·집계 가능해야 한다.

### 5.5 신규 덱 / 카드 편입
- **FR-5.1** 신규 덱은 **제로샷 평가**(기존 정책으로 즉시)와 **학습 후 평가**(파인튜닝 후)를 **둘 다** 측정할 수 있어야 한다(일반화 vs 진짜 강함 분리).
- **FR-5.2** 파인튜닝은 **기존+신규를 섞어** 학습해 기존 덱 망각(catastrophic forgetting)을 방지한다.
- **FR-5.3** 신규 카드는 **vocab에 새 슬롯 추가**로 편입하되 기존 임베딩을 흔들지 않아야 한다.
- **FR-5.4** (참고) 제로샷 일반화는 신세트=신효과 특성상 낮게 나옴을 정상으로 간주한다(=현실 신세트 초반 재현).

### 5.6 대량 병렬 대전 / 실행
- **FR-6.1** 다수 매치를 **병렬 실행**해 경험 수집·평가·통계를 벌 수 있어야 한다(`HeadlessEpisodeBatchRunner` 재사용).
- **FR-6.2** 결정론(시드) 재현을 보장한다(리플레이·검증·분쟁의 기반).
- **FR-6.3** 규모가 병목이면 **직렬화 승급(바이너리) 또는 C# 인프로세스 롤아웃 + ONNX 정책**으로 확장 가능해야 한다.

### 5.7 로그 / 계측
- **FR-7.1** 로그 레벨은 **OFF / RESULT / REPLAY / ANALYSIS / TRACE**(누적적)를 지원한다.
  - OFF=대량 학습 성능용(오버헤드 0), RESULT=승패·매치메타, REPLAY=굵은 사건(사람이 알아볼 선),
    ANALYSIS=효과 발동 등 잔 사건(밸런스), TRACE=엔진 내부(디버깅).
- **FR-7.2** 계측은 **카드가 아니라 프리미티브·단일 뮤테이션 sink에 자동**으로 심는다(≈88개 지점, 카드 3918개 소급 불필요).
- **FR-7.3** emit은 **레벨 가드**로 비활성 시 비용이 사실상 0이어야 한다(대량 대전 성능 보전).
- **FR-7.4** 사건 이벤트는 **육하원칙 필드**(seq/type/actor/subject:cardId/target/zoneFrom·To/cause)를 갖는다.
- **FR-7.5** semantic 효과 태깅(정교 분석 축)은 **후속**(실제 분석 니즈 + 세트 포팅 후). 계측 지점만 자리 확보.

### 5.8 밸런스 분석 (후속)
- **FR-8.1** 로그를 집계해 **카드 채용률·승률 상관·기여도**를 산출할 수 있어야 한다.
- **FR-8.2** OP/데드 카드, 색·타입 밸런스, 파워크리프, 메타 다양성, 선후공 밸런스를 진단할 수 있어야 한다.
- **FR-8.3** 발매순 개방 실험에서 **실제 역사(너프/메타)와 대조**할 수 있어야 한다.
- **FR-8.4** 통계적 엄밀성(표본·신뢰구간·상관/인과 구분)을 갖춘다.

## 6. 비기능 요구사항 (NFR)
- **NFR-1 조각 재사용**: 아레나와 엔진·seat 프로토콜·관측·로그·스냅샷·카드-ID·정규화기를 공유(중복 구현 금지).
- **NFR-2 대량 대전 성능**: 로그 OFF·인프로세스 경로에서 수십~수백 매치 병렬이 현실적이어야 한다.
- **NFR-3 결정론**: 동일 시드+행동열=동일 궤적(검증·리플레이·분석 신뢰의 근거).
- **NFR-4 유연한 실험 구성**: 덱 공급원·정책·보상·로그레벨을 설정으로 조합(코드 수정 최소).
- **NFR-5 점증적 가치**: 카드 포팅 진척에 비례해 "메타 재현·밸런스"의 인사이트가 자란다(=포팅 검증 도구도 됨).
- **NFR-6 YAGNI**: 미래 니즈(제로샷·정교 태깅·성향 보상)를 미리 만들지 않되, 나중 소급 부담이 유한하도록 지점만 확보.

## 7. 가정
- **A-1** 카드 효과가 포팅된 만큼만 "메타·밸런스"가 의미를 가진다(장기·점증 시스템, 포팅과 병행).
- **A-2** 초기 카드풀 = ST1~3 / BT1~3 / 소수 P카드. 초기 덱 = **운영자가 던지는 과거 레시피**.
- **A-3** 신세트 ≈ 신효과 → 제로샷은 낮음, 학습 편입으로 해결(현실 재현).
- **A-4** 안쪽 정책이 신뢰할 만해진 뒤에야 바깥 GA의 승률 평가가 의미를 가진다(순서: 플레이→덱).

## 8. 미해결 / 다음에 짚을 것
- 리그 상대 샘플링 가중치 구체값, 스냅샷 주기.
- 보상이 sparse로 안 붙을 때의 최소 셰이핑 형태·감쇠 정책.
- 병렬 규모별 직렬화 병목 임계점, ONNX 전환 시점.
- 덱 성향을 "보상"이 아닌 "평가 지표"로 쓰는 분석 설계(관찰 순수성).
- GA 활성 시점 판단 기준(안쪽 정책 수렴 척도).
