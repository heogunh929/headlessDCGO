# 등재된 예외 (sanctioned exceptions)

기준은 `AS-IS 동일로직 동일경로`이며, **여기 등재된 항목만** 의도적 이탈로 인정한다.
등재되지 않은 차이는 전부 결함으로 취급한다. 등재 권한은 사용자에게만 있다.

---

## E-01 · 필드 슬롯 개수 제한 (배틀에어리어 용량)

**등재일** 2026-07-28 · 사용자 선언

**AS-IS 동작**
`Player.fieldCardFrames` = 고정 슬롯 배열. 빈 슬롯이 없으면 플레이·이동을 거부한다.
- `Permanent.CanMove` — `fieldCardFrames.Count(empty && battleArea) == 0` → `return false`
- `PlayPermanent` — 빈 프레임 탐색 실패 시 플레이 불성립

**이탈 사유**
AS-IS의 슬롯 배열은 **화면 배치를 위한 그래픽 구조**다. 실제 디지몬 카드게임 룰에는 배틀에어리어
개수 제한이 없다. 따라서 TO-BE는 이 제한을 **의도적으로 구현하지 않는다**.

---

### 2026-07-29 개정 — 실현 방식이 바뀜 (사용자 확정)

AS-IS 소스를 그대로 돌리는 방식으로 전환(`docs/roadmap.md`)했으므로,
"용량 판정을 구현하지 않는다"는 더 이상 성립하지 않는다.
AS-IS의 `CanMove`·`PlayPermanent`가 그대로 실행되기 때문이다.

**새 실현 방식**: 슬롯 배열의 **출처**를 조정한다.

`Player.cs:23-44`가 `BattleAreaFrameParent.childCount` / `GetChild(i)` 로 `fieldCardFrames`를
구성한다 — 즉 **슬롯 개수가 유니티 씬 계층에서 나온다.** substrate가 이 계층을 합성할 때
**충분히 크게** 만들면 용량 판정이 사실상 걸리지 않는다.

- AS-IS 코드 경로는 **그대로 실행된다**(용량 판정 로직 포함). 코드를 고치지 않는다
- 바뀌는 것은 substrate가 공급하는 **슬롯 개수뿐**이다
- 면제 범위는 종전대로 **용량 판정에 한한다**

> 아래 파생 4종이 결함이라는 판정은 old-TO-BE(손포팅)에 대한 것이었다.
> AS-IS를 그대로 돌리면 프레임 ID 재해석·`PermanentFrame != null` 게이트 소실·
> 조그레스 생존자 위치 미보존·`CanPlayAsNewPermanent` 대체는 **애초에 발생하지 않는다.**

**적용 범위 — 용량 제한에 한정**
이 예외가 면제하는 것은 "슬롯이 꽉 차면 막는다"는 **용량 판정뿐**이다.
슬롯 모델을 없애면서 파생된 다음 항목들은 **예외가 아니라 결함이다** (2026-07-28 사용자 확인).
용량 가드와 별개 사안이므로 수리 발주 대상으로 남긴다:

- 프레임 ID를 필드-퍼머넌트 리스트 인덱스로 재해석 (AS-IS는 안정적 슬롯 번호, 포트는 퇴장 시 밀리는 순번)
- `PermanentFrame != null` 게이트가 무조건 실행으로 바뀐 것 (`CanBlock`·`CanAttackTargetDigimon`)
- 조그레스 생존자의 필드 위치 미보존
- `CanPlayAsNewPermanent`가 프레임 스캔 대신 비용 검사로 대체된 것

**분류** 감사 목록에서 `EXCEPTION`으로 표기. 수리 발주 대상이 아니다.
