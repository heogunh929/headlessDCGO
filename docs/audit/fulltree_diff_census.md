# 전수 diff census — AS-IS ↔ TO-BE

측정일 2026-07-29. **에이전트 0기 · 순수 기계 측정.**

기준: TO-BE(`src/HeadlessDCGO.Engine/Assets/Scripts/`)는 AS-IS(`DCGO/Assets/Scripts/`)의 축자 사본이어야 한다.
따라서 `diff`가 곧 결함 측정이다.

## 방법

AS-IS는 CRLF·일부 Shift-JIS, TO-BE는 LF다. 줄끝을 정규화해 대조했다.

```
diff --strip-trailing-cr -u0 DCGO/Assets/Scripts/<P> src/HeadlessDCGO.Engine/Assets/Scripts/<P>
```

grep은 반드시 `-a`(`--binary-files=text`)를 붙인다. AS-IS에 비-UTF8 바이트가 있어
붙이지 않으면 해당 파일이 **무증상으로 스킵**된다(실제로 1차 측정에서 전 마커가 0으로 나왔다).

산출물: `fulltree_diff_baseline.tsv`(페어별 차이량 4,266행) ·
`fulltree_residual_by_file.tsv`(잔여 집중도 650행) ·
`fulltree_asis_only.list` · `fulltree_tobe_only.list`

### 1번 착지 (2026-07-29)

도구 `tools/CommentStripper/`(Roslyn trivia 전용).
판정 규칙 = TO-BE 주석의 정규화 텍스트가 대응 AS-IS 파일의 주석 집합에 있으면 보존, 없으면 삭제.

- 삭제 18,365단위 / 물리 17,929줄 · 보존 189단위
- **토큰 동등성 650/650 PASS** — 적용 전 축자 백업 대비 독립 재대조.
  코드가 한 글자도 바뀌지 않았음의 기계 증명
- 빌드 오류 0 / 경고 2,131 — 경고 멀티셋 전후 완전 동일
- 650파일 총 차이 **131,921 → 114,514행**

부수 확인: AS-IS 9개 파일이 Shift-JIS(cp932)라 UTF-8 엄격 디코드가 실패한다.
폴백을 넣어 일본어 AS-IS 주석이 정상 매칭·보존됐다.

> **빌드 경고 관련 정정**: 증분 빌드(`-t:Rebuild` 없이)는 컴파일을 건너뛰고
> "경고 0개"를 출력한다. 진짜 베이스라인은 **경고 2,131건**(CS8625 1,035 · CS8602 516 · CS8603 172 등
> nullable 계열 위주)이다. 빌드 게이트를 인용할 때 `-t:Rebuild`를 붙이지 않으면 허위 수치가 나온다.

## 7. 이 작업이 드러낸 결함

주석 삭제가 **미포팅을 가리고 있던 파일 2개**를 노출시켰다.
TO-BE에 코드가 전무하고 전부 TO-BE 작성 STOP 사유 주석뿐이라 삭제 후 0바이트가 됐다.

| 파일 | AS-IS | TO-BE(현재) |
|---|---:|---:|
| `Script/CutInProcess.cs` | 110줄 | 0줄 |
| `Script/SelectCardPanel.cs` | 688줄 | 0줄 |

0바이트가 정직한 상태이므로 복원하지 않고 결함으로 등재한다.
**주석이 상태를 은폐하는 실증 사례가 하나 더 늘었다.**
