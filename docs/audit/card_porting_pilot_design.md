# 카드 포팅 파일럿 — Sonnet 4.6 실측 설계 (draft v0.1)

- 작성일: 2026-07-04. 상태: 설계(실행은 사용자 승인·API 키 필요).
- 기준: [card_porting_database_design.md](card_porting_database_design.md)(§0.2 북극성, §9-A 프론티어),
  P-DB1 산출물(`tools/porting/porting_task.py` 태스크 카드), [rl_l4_match_log_design.md](rl_l4_match_log_design.md)(L4 발화 검증).
- 목적: **§9-A의 미해결(시딩 수 229~2,568 범위 중 실제값)을 실측으로 좁힌다.** "가장 가벼운 모델도
  확정적으로 수행"이 목표지만, 우선 **Sonnet 4.6**(사용자 지정, 로컬 경량 모델보다 강함)으로 상한 성공률을
  재서 "레퍼런스 거리별로 유추가 얼마나 성립하는가"를 확정한다. Sonnet이 실패하면 더 가벼운 모델은 당연히
  실패 → 티어별 Sonnet 성공률이 **경량 모델 실현 가능성의 낙관적 상한**.

## 1. 무엇을 측정하나 (핵심 질문)

**질문: 포팅 모델은 레퍼런스와 대상의 "거리"가 얼마까지 벌어져도 정확히 유추하는가?**
이 함수가 곧 시딩 수를 정한다 — 거리 허용폭이 넓을수록(느슨한 시그니처로 커버) 강모델이 심을 레퍼런스가
적어진다(§9-A 프론티어의 실측 해).

측정 = **3티어 조건**에서 각각 성공률:

| 티어 | 레퍼런스 조건 | 순도(설계 실측) | 기대 |
|---|---|---|---|
| **T1 exact** | 같은 S5 시그니처의 이미 포팅된 카드 | 89% | 높음(거의 인자 채우기) |
| **T2 family** | 액션 태그만 같은(구조 다를 수 있는) 카드 | 56% | 중간 — **핵심 측정점** |
| **T3 cold** | 레퍼런스 없음(대상 AS-IS만) | — | 낮음(baseline, 레퍼런스 가치 정량화) |

T1↔T3 성공률 차 = **레퍼런스가 유추에 기여하는 크기**. T2 성공률 = **느슨한 시그니처로 확산해도 안전한가**
(높으면 시딩 수↓, 낮으면 순도-우선 S5 유지 = 시딩 수 큼).

## 2. 대상

- **세트 = BT1**(발매순 첫, pending 88장, 준비도 코호트에서 `ready`+`review` 혼재 — §0.2 초기 세트 100%).
- 표본: 각 티어 **최소 15장**(BT1 내 shape·액션 다양성 커버). T1은 exact 레퍼런스 보유 카드에서, T2는
  액션 패밀리 레퍼런스만 있는 카드에서, T3은 T1/T2 대상 중 레퍼런스를 의도적으로 가린 대조군.
- blocked(갭 프리미티브) 카드는 제외(§0 준비도).

## 3. 모델 / 호출 (Anthropic Python SDK)

- 모델 = **`claude-sonnet-4-6`**(사용자 지정). 사고 = **adaptive**(`thinking={"type":"adaptive"}`).
  effort = `high`(코드 정확성 작업). 큰 출력 대비 **스트리밍**(`messages.stream` + `get_final_message`).
- 인증 = 환경(`ANTHROPIC_API_KEY`) 또는 `ant auth login` 프로파일(SDK 기본 클라이언트가 자동 해석).
- 입력(사용자 턴) = P-DB1 태스크 카드(대상 AS-IS + 레퍼런스 AS-IS→포팅본 + 유추 지시). 시스템 프롬프트 =
  구조 동일 원칙([card_porting_standard.md]) 요약 + "레퍼런스의 변환을 그대로, 인자만 대상값으로. 구조·팩토리·
  타이밍·네임스페이스 규칙 유지. 추측·가드 완화 금지. 코드 블록 1개만 출력." (프롬프트는 과도하게 처방하지 않음.)
- 출력 = `.cs` 1파일. 캐싱: 시스템 프롬프트 + 티어 공통부에 `cache_control`(반복 호출 비용↓).

## 4. 검증 게이트 (자동 → 사람)

BT1 pending은 per-card 단언 테스트가 아직 없다 → 게이트를 계층화:

1. **G1 컴파일**(자동·필수): 생성 `.cs`를 엔진에 넣고 `dotnet build`. 실패 = FAIL(구조 오류).
2. **G2 구조 동일**(자동): 생성본이 레퍼런스 포팅본과 **같은 팩토리·타이밍·커먼즈 골격**인가(IR 재추출로
   대조 — 대상 AS-IS의 IR과 생성본이 부르는 프리미티브 집합 일치). 인자값만 달라야 PASS.
3. **G3 L4 발화**(자동·행동): 포팅 카드를 포함한 덱으로 대량 셀프플레이 → **L4 ANALYSIS 로그에서 그 카드의
   효과 이벤트가 실제로 fire**하는가([rl_l4_match_log_design.md] §5, "green인데 inert" 자동 탐지). 정적효과는
   RuleAudit/게이트 질의로 대체.
4. **G4 사람/강모델 리뷰**(최종): G1~3 통과분을 강모델이 AS-IS 대조 스팟체크(충실도 최종 판정). 파일럿에선
   전수, 본편에선 샘플.

성공 = G1∧G2∧G4(행동 카드는 +G3). 티어별 성공률 = G-통과 카드 / 시도 카드.

## 5. 산출 / 게이트(파일럿 종료조건)

- 티어별 성공률 표(T1/T2/T3) + 실패 사유 분류(컴파일 / 구조 이탈 / 인자 오류 / inert / 충실도).
- **결론 도출**: T2 성공률이 높으면(예: ≥80%) → 느슨한 액션-패밀리 시그니처 채택, 시딩 수 대폭↓(§9-A
  재계산). 낮으면 → 순도-우선 S5 유지, 시딩은 강모델 몫으로 큼. T3 대비 T1/T2 상승폭 = 레퍼런스 ROI.
- **경량 모델 함의**: Sonnet이 T2에서 실패하면 그 티어는 경량 모델 부적합 확정 → 경량 모델은 T1(exact)
  전용으로 배치하고 T2/T3은 강모델. Sonnet이 T2 성공이면 경량 모델 파일럿(별도)의 대상 후보.
- run-tests green + RuleAudit 0 유지(생성 카드가 회귀를 안 냄).

## 6. 비용 / 규모 감각

- 카드당 입력 ≈ 태스크 카드(대상+레퍼런스 2쌍) 대략 2~6K 토큰, 출력 ≈ 0.5~2K. 45장×3티어 ≈ 135호출.
- Sonnet 4.6 $3/$15 per MTok → 파일럿 총비용 대략 수 달러 규모(캐싱으로 추가 절감). 승인 후 실행.

## 7. 하네스 (구현 위치)

`tools/porting/pilot/port_with_sonnet.py`(신규): DB에서 티어별 대상 선정 → `porting_task.py`로 태스크 카드 →
Sonnet 호출 → `.cs` 저장(격리 브랜치/worktree) → G1 컴파일 → 결과 JSONL. G2~G4는 후속 스텝(별 스크립트).
**세팅 트랙과의 인터페이스**: 이 하네스가 "1카드 = 1작업"의 참조 구현 = 로컬 모델 오케스트레이터가 나중에
같은 태스크 카드 포맷을 소비(§7 직교). 즉 파일럿 하네스가 세팅 트랙의 계약 예시다.

## 8. 미해결
- G3 발화 자동 판정의 카드별 기대 이벤트 매핑(효과→GameEventType) — 액션 태그에서 유도 가능한지 실측.
- 격리 실행: 생성 카드를 worktree에 넣고 빌드(메인 오염 방지) vs 임시 파일. worktree 권장.
- 경량 모델(로컬) 파일럿은 별도 — 이 설계는 Sonnet 상한 측정에 한정(세팅 트랙 확정 후 경량 파일럿).
